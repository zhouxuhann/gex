# 0DTE 收盘前数据丢失分析

**日期**: 2026-04-15
**现象**: GEX Monitor 在美东 15:24 (JST 04:24) 开始出现 "No valid data from 40 contracts"，距收盘约 36 分钟

## 时间线

| 时间 (ET) | 时间 (JST) | 事件 |
|------------|------------|------|
| ~15:24 | 04:24:20 | 第一次 "No valid data from 40 contracts" |
| ~15:30 | 04:30:13 | Error 200: IB 返回 20260414 期权合约"未找到证券定义"（strike 644-659，远端 OTM） |
| ~15:31 | 04:31:10 | 市场数据场重连 (Warning 2119→2104)，属正常重连 |
| ~15:31 | 04:31:38 | 持续无数据，40个合约全部无报价 |

## 根因

**0DTE 临近到期，IB 逐渐停止提供远端 strike 的实时报价。**

具体表现：
- expiry=20260414 的 0DTE 合约，在收盘前 30+ 分钟开始丢失数据
- 先是 OTM 远端 strike (644-659) 报 Error 200（证券定义找不到）
- 随后全部 40 个合约无有效报价
- 这不是并发订阅上限问题（Error 162）或网络断线，而是 IB 对即将到期合约的正常行为

## 排除的其他假设

| 假设 | 排除原因 |
|------|----------|
| 并发订阅上限 | 无 Error 162 或 Error 1019，且 KDJ Trader 同时运行正常 |
| 市场数据场断线 | 2119/2104 发生在 04:31，但 04:24 已开始丢数据 |
| 合约过期 | 4/14 合约在收盘时才真正到期，15:24 尚未到期 |

## 影响

- GEX 数据在收盘前 ~30 分钟出现空白
- DB 写入中断（4/14 最后记录停留在 19:37:20 UTC = 15:37 ET）
- 收盘前的重要 GEX 变化（pin risk、gamma squeeze 等）无法捕获

## 可能的改进方向

1. **提前告警**: 当 valid contracts < 50% 时发 warning，区分"0DTE 临近到期"和"订阅异常"
2. **降级模式**: 远端 strike 丢失时，只用剩余有效 strike 计算 GEX（标记为 partial）
3. **切换合约**: 收盘前 30 分钟自动切换到下一个 expiry，继续监控
4. **日志区分**: 在 log 中区分 "0DTE expiring" vs "subscription lost"，避免混淆诊断
